# OneNote Ink Math: Roadmap

**Spec:** `docs/superpowers/specs/2026-11-09-onenote-ink-math-design.md` (approved 2026-11-09)

The spec covers several subsystems that can be built and tested separately. Each milestone gets its own detailed plan, written when the milestone before it (or its gate) is done, because earlier results change later plans. In particular, the recognizer chosen in M1 shapes M4 and M5.

| # | Milestone | Depends on | Detailed plan |
|---|---|---|---|
| M1 | Handwriting accuracy spike + go/no-go gate | user writes samples on the Surface | `2026-11-09-m1-handwriting-spike.md` |
| M2 | Solver engine (SymPy: operations, key steps, verification, "keep going or stop?" every 20 s) | nothing (can run in parallel with M1's sample writing) | written next |
| M3 | OneNote bridge: C# COM add-in, Math ribbon tab, read lasso ink, write answer to page; registers for 32-bit and 64-bit | .NET SDK install | after M2 |
| M4 | Recognizer service: chosen model, symbol confidences and alternatives, personal tuning, learning from corrections | M1 result | after M1 gate |
| M5 | Confirm panel: ink snippet, tap-to-fix chips (symbol and structure), action menu, Type it instead | M3, M4 | after M4 |
| M6 | Integration + Surface install script + acceptance on the Surface (latency targets, 64-bit) | M2–M5 | after M5 |
| M7 | Online reader (conditional: only if the second fallback in spec §6.3 triggers) | M6 | if needed |

**Gate after M1:** pass = on the personal test set, ≥70% of problems need zero fixes and ≥95% need ≤2 fixes, after tuning on the user's samples. On a fail, follow spec §6.3's fallback order (1: accept more taps; 2: online reader).
